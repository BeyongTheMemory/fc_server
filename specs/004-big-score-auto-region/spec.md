# 004：大数修为与自动地区榜

日期：2026-10-31。状态：待后端 agent 实施；本文不是已上线能力。

用户确认：修行榜分天榜（全服）、地榜（自动获取城市，人数不足回退省份）、人榜（同玩互动好友）。地榜没有手动切换地区。大数修为需支持字符串协议。实现范围为本规格及配套契约、计划、任务；不重写 002 已完成的登录/好友榜。

## 现状与问题

- 当前 `/upload_score`、`/fetch_rank` 使用三项成绩：关卡、最后一关修为、整局修为。Go 为 int64，Redis Lua 使用 tonumber，MySQL 为 BIGINT；配置默认修为上限 10^15，最高不能超过 JS 安全整数。只改 JSON 类型不足以解决排序和存储精度。
- 客户端第 19～27 关为真仙、金仙、太乙前中后期；第 28 关为大罗 1，目标 11812500000，此后每层 ×3.5 并向上取整。约大罗 12 的目标超过 Number.MAX_SAFE_INTEGER，不能再用 Number 承诺整数精确。
- 客户端当前计分、目标和存档仍为 Number。超过安全整数时不上传。将已经失真的 Number 转 string 无法恢复精度；前端精确计分/存档迁移另行实施，后端完成不代表游戏全链路完成。
- 微信登录及头像昵称不返回可信省市；现有地榜依赖客户端提交 location，尚无经纬度解析服务。

## 用户行为与验收

### A. 大数成绩完整保留并正确排序

1. 同关卡上传 `9007199254740992` 与 `9007199254740993`，后者严格领先，返回值逐位不变。用超过 int64 和 100 位的分数重复验证。
2. 比较顺序保持关卡降序 → 本关修为降序 → 整局修为降序 → 达成时间升序，完全相等时保留先达成记录。不能用普通字典序导致 `9 > 10`，不能通过浮点数打包三项成绩。
3. best、self_score、列表条目、全服/地区/好友、总/月/周窗口均使用同一表示与比较规则。前 100 名外仍能查询自己的精确名次。
4. 重复、较低、并发上传不会降分、重复成员或刷新原达成时间；Redis→MySQL→恢复之后结果一致。
5. 新旧客户端并存：旧路由维持数值契约，新路由使用字符串。超出旧客户端能力时明确升级错误，不能截断、饱和或返回不安全 JSON number。

### B. 自动进入所属地区榜

1. 玩家主动开启定位用途授权；已授权后可自动 `wx.getFuzzyLocation`。前端提交模糊坐标，后端解析并保存标准省市，不让玩家手填或切换地区。
2. 同一账号后续上传与拉榜默认使用同一份服务端地区。每个时间窗口城市人数不足 10（沿用 REGION_MIN_PLAYERS）时分别回退省榜，前端展示实际 scope/address。
3. 未授权、拒绝、接口未开通、解析超时、海外或无法确定省份时，不填虚构城市；天榜、人榜和单机仍可用，地榜给可理解的空态/重试。
4. 已授权但暂时定位失败不清掉最后一次有效省市；主动撤回位置用途时可删除已保存地区，之后上传只参与全服及好友榜。无后台持续定位。
5. 解析不会把此前未带地区的全服历史成绩伪造成该地区成绩。地区变化后只影响后续提交与查询，既有地区窗口纪录按现有“上报时地区”语义保留；不要在查询时复制最好成绩进入任意新地区。

## 必须满足的约束

- 两项 cultivation 的规范形式：`0` 或 `[1-9][0-9]*`，JSON string，非负整数，无前导零、空白、正负号、小数、科学计数法、全角数字。整局修为不得小于本关修为。
- 默认最大长度 1024 位，作为有界资源保护配置 `MAX_CULTIVATION_DIGITS`（允许 16～4096，配置与键编码一致）；超过返回明确 400，不吞掉低位。并非承诺数学上无限存储。stage 保持 JSON 安全整数，沿用 MAX_STAGE。
- 大数不得经过 Go float64/int64、Redis Lua tonumber、Redis ZSET score 的 IEEE754 数值路径。可以使用规范字符串的长度+逐位比较，必要时用 math/big；不要把每个榜全量拉回 Go 排序。
- 原成绩、用户归属、达成时间、窗口、待备份标记都必须迁移。上线前备份/可恢复演练；不能清空用户成绩充当迁移。旧数据中已经丢失的精度无法补回。
- 地图供应商密钥仅在后端；只需模糊定位，不请求精确定位替代。省市标准化、直辖市/无市级名称/海外处理规则统一，不信任客户端随意命名的地区。
- 服务端只长期保存必要的标准省市与解析时间。原始坐标仅用于本次上游请求，不落库、日志或错误响应。请求限流、上游超时、失败分类、鉴权沿用现有规范。
- 用户的小关入口快照策略保持原样；不增加购买、领奖后的游戏存档落盘。此次不做云存档、奖励、反作弊或微信完整通讯录。

## 前端与平台依赖

- 新版成绩上报需与前端精确整数/小数计分方案及存档迁移共同验收；在此之前前端保留 Number 安全上限，不从近似浮点数伪造精确字符串。
- 新榜单可独立接收并格式化十进制字符串，不转换为 Number 后展示或排序。
- 微信后台需开通模糊定位和同玩互动好友接口，配置隐私用途。定位 `scope.userFuzzyLocation` 与好友 `scope.interactedUserInfo` 独立于头像授权；拒绝后只通过玩家主动操作设置入口恢复。
- 地图供应商账号、密钥与生产合法域名由部署者配置；实现可用 fake provider 完成可重复验收，不自动创建付费服务。
